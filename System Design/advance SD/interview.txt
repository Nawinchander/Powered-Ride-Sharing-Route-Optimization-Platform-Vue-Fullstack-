Node.js
Q1. Why Node.js for Ride Sharing?

Answer

Node.js uses an event-driven, non-blocking I/O model, making it well suited for handling many concurrent requests such as ride bookings, live tracking, and notifications.

Q2. Why Express?

Answer

Express simplifies routing, middleware management, and API development while remaining lightweight.


Q3. Why use the Service Layer?

Answer

It keeps business logic separate from controllers, improving maintainability and testability.

Q4. Why Repository Pattern?

Answer

Repositories isolate database access from business logic, making it easier to swap databases or mock data in tests.


MongoDB
Q5. Why MongoDB instead of MySQL?

Answer

Ride-related data (locations, driver status, ride history) often evolves. MongoDB's flexible schema adapts more easily to changing requirements.

Q6. Why index location?

Answer

A geospatial (2dsphere) index speeds up nearby-driver searches significantly compared to scanning every driver.


Redis
Q7. Why Redis?

Answer

Redis stores frequently accessed or short-lived data such as online drivers, cached routes, and user sessions, reducing database load.

Q8. What should be cached?

Answer

Nearby drivers
Popular routes
Fare estimates
Active ride sessions
User session data


Socket.IO
Q9. Why not use polling?

Answer

Polling repeatedly requests updates even when nothing changes. Socket.IO pushes updates instantly, reducing latency and unnecessary network traffic.

Vue.js
Q11. Why Pinia?

Answer

Pinia provides centralized state management with a simpler API than Vuex and is the recommended state management solution for Vue 3.

Q12. Why Axios?

Answer

Axios supports interceptors, automatic JSON transformation, request cancellation, and consistent error handling.


Authentication
Q13. Why JWT?

Answer

JWT enables stateless authentication, making horizontal scaling easier because servers don't need shared session storage.

Q14. Where should JWT be stored?

Answer

For production, an HttpOnly Secure Cookie is generally preferred to reduce XSS risk. For a demo project, localStorage is acceptable if you understand its security trade-offs.
