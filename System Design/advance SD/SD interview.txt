System Design

Q15. How do you assign a driver?

Answer

Query nearby available drivers.
Filter by availability and vehicle type.
Rank using distance, rating, and idle time.
Select the best candidate (e.g., using a priority queue).
Send the request through Socket.IO.



Q16. How would you scale to 1 million users?

Answer

Add a load balancer.
Run multiple backend instances.
Cache hot data in Redis.
Use MongoDB sharding/replica sets.
Move notifications to BullMQ workers.
Serve frontend assets via a CDN.
Split into microservices as the application grows.


Q17. How do you avoid duplicate ride bookings?

Answer

Use idempotency keys or database transactions/locks so repeated requests don't create multiple rides.

Q18. How do you handle driver disconnects?

Answer

Detect socket disconnections, mark the driver offline, notify the rider if needed, and search for another available driver.



Q19. Why use BullMQ?

Answer

Background jobs such as emails, push notifications, receipts, and analytics should not block the main API request. A queue improves responsiveness and reliability.

Q20. If MongoDB goes down, what happens?

Answer

The API should fail gracefully, return meaningful errors, retry transient operations where appropriate, and rely on replica sets or backups for recovery.
